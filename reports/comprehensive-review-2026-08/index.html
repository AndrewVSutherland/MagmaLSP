MagmaLSP: Comprehensive Review & Overhaul

August 12, 2026 · branch comprehensive-review · reviewed at 0f07757 (post PR #11) · Magma 2.29-9, local Ryzen AI Max+ 395 box
Review method: five parallel deep-review agents (DB layer, LSP server/analysis, Magma validation backend, agent-facing front-ends, eval/validation infrastructure) + hands-on verification of every claimed defect against live Magma.

Executive summary

The foundation is genuinely good: the core-plus-thin-adapters architecture is right, the golden Magma invocation recipe is implemented faithfully, the signature-DB build pipeline survived a Magma version bump (2.29-7 → 2.29-9) exactly as designed, and the eval write-ups are unusually honest about their own limitations. Nothing found in this review changes the project's architecture.

What the review found instead: the tool was mistuned for its stated audience — an LLM (especially a small one) iterating against it. The single biggest failure mode of a weak model writing Magma is a plausible wrong name, and lookup misses were near–dead ends (prefix suggestions only, no search-by-concept). The check pipeline crashed rather than degraded without Magma, reported a confident OK on timeouts, false-flagged the two most common real file shapes (intrinsic package files and load-based scripts), could be made to execute code during the "safe" pass via wrapper escape, and run reported errors at temp-file line numbers with an unbounded output that could dump 3 MB into an agent's context. On top of that, the DB extractor had four correctness bugs that fed wrong signatures to everything downstream.

All of the above is fixed on this branch, plus the two highest-value additions for small models: keyword search over the signature corpus and a static pitfall/arity layer that catches LLM-typical mistakes before Magma runs. Headline numbers:

A satisfying side effect: the new static arity checker, audited against 4,031 sources of known-correct code (the entire spec-attached package corpus plus all handbook example programs), produced 25 flags — and every inspected flag is a latent bug in Magma's own package tree (e.g. six 3-argument calls to the 2-argument AbsolutelyIrreducibleModules in GrpFP/SolQ/sq_proc.m; a 2-argument NumberField(R1,R2) that no overload accepts). The check's effective false-positive rate on correct code is ≈0, and the flag list may be worth passing to the Magma developers.

1 · What was reviewed and how

Five agents each read their subsystem completely and were required to verify claims empirically (running Magma 2.29-9, parsing the real package tree, exercising the CLI/MCP surface) before reporting. I independently read the full source (~2,500 lines), reproduced the key findings by hand, and re-derived the priority list. The environment itself was part of the review: this repo's facts were established on the old GCP VM with Magma 2.29-7; this box runs 2.29-9, which surfaced one genuine behavioral drift (below) and several stale documented numbers.

2 · Findings and fixes by area

2.1 Signature DB (the data everything trusts)

4 extraction bugs All verified against the corpus and the name; oracle, all fixed:

  • Ditto docs resolved by name, not file order. Magma's {"} means "same doc as the immediately preceding intrinsic in the file", chaining across names. 74 intrinsics had wrong or missing docs (e.g. Points(C::CrvHyp[FldAlg]) carried the doc of a different calling convention). db/package.py
  • Untyped args silently dropped. intrinsic F(R::RootDtm, w1, w2) registers as (R, w1::Any, w2::Any) in Magma, but the extractor produced a phantom 1-argument signature — wrong arity for 109 intrinsics, exactly the misinformation that makes an LLM write a call that crashes. db/package.py
  • Merge key ignored ~ and type spellings. ChangeUniverse(~S, W) vs ChangeUniverse(S, W) — the function/procedure distinction small models most need — collided; 81 real in-place overloads were dropped as "duplicates". Meanwhile Q::[RngIntElt] vs SeqEnum[RngIntElt] spellings failed to collide, double-listing ~915 overloads. db/build.py
  • Probe parser corrupted by optional-parameter blocks. name; output interposes [ Bound, ... ] blocks between signature and doc; the parser stored the bracket content as the doc. Fixed and turned into a feature (next item). db/probe.py

New: kernel doc harvest ListSignatures provides no doc strings, so 35% of names had none — but the REPL name; form prints docs and optional-parameter names. The build now probes every undocumented name after the merge (parallel, ~500 names/batch): +5,711 docs and +622 optional-parameter lists for ~zero extra build time (build is ~30 s total on this box). Doc coverage: 65% → 95.7% of names.

Also fixed: relative --package-root silently produced a package-empty DB; MAGMA_LSP_DB set-but-missing silently fell back to unrelated caches; the loader now prefers the artifact matching the installed Magma version and warns on staleness (previously a 2.29-7 DB would serve silently forever after an upgrade); the category regex accepts 2.29-9's new _-prefixed category.

2.2 Magma validation backend (the error signal)

correctness safety The single function-wrap check was structurally wrong for the two most common real file shapes, both verified on 2.29-9:

  • An intrinsic … end intrinsic; file (the primary package form, 1,776 files in the official tree) got a phantom bad syntax at 1:1 on every open/save — a persistent bogus error at the top of a correct file, the single worst thing you can show an agent.
  • A stray top-level end function; (a realistic mid-edit state) closed the wrapper early: phantom errors past the end of the file, and — worse — the remainder of the file executed during the advertised no-execution pass (verified: it wrote a file to disk).

syntax_check now dispatches on a tree-sitter pre-scan: files that don't parse are reported from tree-sitter and never reach Magma; package files are checked via Attach() (real positions, nothing executes); plain scripts use the wrap with load directives blanked out. Additionally: positioned error blocks are now filtered to our temp file, so program output that merely looks like a Magma error block can no longer fabricate or mask diagnostics; Magma's tab-expanded columns are mapped back to character offsets; past-EOF errors clamp with an "unterminated block?" hint.

version drift One real behavioral correction to CLAUDE.md §5: undefined-identifier errors are collected per top-level statement — within one function body (i.e., inside the wrap), Magma stops at the first undefined name. The static unknown-name check is therefore more valuable than documented (it reports all of them at once), which motivated running it always, not only when Magma is off.

2.3 Agent-facing surface (MCP / CLI / frontend)

degraded modes check crashed with a raw traceback when Magma was absent (discarding the static findings it had already computed); a timed-out check returned a confident OK; a missing DB message named a command that isn't on the user's PATH; the MCP server cached a missing DB as permanently-None; the handbook enrichment was silently absent on this box for every MCP/CLI lookup (the install-dir derivation assumed the GCP layout); .mcp.json set MAGMA_PATH but no code read it. All fixed — every degraded mode now produces an explicit note, and INCONCLUSIVE is a first-class outcome.

output discipline run reported errors at temp-file coordinates (line 7 for user line 2) with the temp path leaked, returned exit 0 on runtime errors, and could return megabytes. Now: user-coordinate remapping, SetQuitOnError exit codes, head+tail truncation preserving the tail (where errors and results live). lookup of a 258-overload operator dumped 20 kB; overloads are now capped, documented-and-common-types first, with an elision note. Duplicate static+Magma reports of the same undefined name (with contradictory advice — the static hint said "import it" for what was actually a typo) are merged, with suggestions attached to Magma's terse message.

new capabilities Aimed squarely at the small-model failure modes the evals identified:

  • magma_search(query) — keyword search over names + 9,860 doc strings (tf-idf with soft-AND coverage). The missing entry point when the model knows the concept but not the name.
  • Did-you-mean everywhere — camelCase-token + edit-distance ranking with a cross-system alias table: FactorInteger → Factorization, NumPoints → NumberOfPoints, PrimeQ → IsPrime, length → '#'. Wired into lookup misses, check diagnostics, and the LSP lint.
  • Forgiving lookup resolution — case-insensitive fallback and operator normalization (# → '#').
  • magma_guide() — a one-page, Magma-verified conventions brief (the trap-benchmark conventions: Subgroups returns class representatives, Factorization returns pairs, Coefficients is constant-first, …; sequence idioms; efficiency habits; the lookup→check→run loop). A small model reads it once instead of paying the probing tax per convention.
  • magma_check executes by default — the 3-arm eval's own takeaway (its one LSP-arm regression came from a trial that skipped the dynamic run). MCP instructions now encode the proven workflow.

2.4 LSP server & static analysis

protocol / responsiveness Every handler ran synchronously on the asyncio event loop — a Magma check or a workspace rescan (measured at 7 s for 1,900 files, on every save) blocked hover/completion/diagnostics for its duration. Handlers now run in pygls' thread pool, publishes are version-checked (stale results are discarded), the workspace scan is mtime-cached (a save re-parses one file), and a failing pass publishes empty diagnostics rather than freezing stale squiggles.

coherence Save-time and keystroke-time diagnostics disagreed: the static pass ran only when Magma didn't, so saving showed fewer findings than typing, and Magma's binding errors false-flagged names defined in sibling files (never filtered against the workspace scan). The static passes now run on every publish; Magma's undefined-name reports are filtered against workspace/loaded-file symbols and deduped against the suggestion-bearing static diagnostics. load "file"; targets are resolved relative to the document and their definitions honored (frontend and server both).

Also fixed: documentSymbol missed named function/procedure definitions entirely (outlines of real files were near-empty) and the func<…>/proc<…> forms (the grammar parses them as constructor; the code referenced node types that don't exist — which also made Helper := func<x | x+1>; a false "unused variable"); loop variables are no longer reported unused (for i := 1 to n is legitimate repeat-n-times); completion's . trigger removed (after R. the valid completions are generator names, not 200 intrinsics); signatureHelp computes the active parameter; selection ranges cover the name token.

2.5 Eval & validation infrastructure

The eval review's verdict, in brief: the scoring core (run the program, compare to precomputed truth — no LLM judge) is trustworthy and none of the committed generations gamed it; but the headline claims outrun the evidence in specific ways worth keeping in mind:

  • "Execution dominates" is partly task-selection tautology — every closed-arm failure on the hard set is a crash, definitionally the failure mode an iterate-on-error loop fixes. Valid as a floor, over-general as a slogan.
  • Statistical support is thinner than the percentages suggest — failures cluster per task (effective n≈20, not 60); closed→lsp alone is p≈0.125 by sign test, significant only pooled with the trap set; raw-vs-lsp differences (59/60 vs 60/60) are pure noise, so "raw edged out lsp" should read "indistinguishable".
  • The efficiency table (raw 1.52 vs lsp 1.07 Magma runs/agent) is not reproducible from any committed artifact — the generation harness lives outside the repo and records no tool-call counts or tokens.
  • The two strategically decisive experiments haven't been run: (1) small models — every generation is Sonnet, yet the target is smaller models, and the "DB is marginal" conclusion may well invert for a model that can't interpret Magma's terse errors; (2) the expensive-probe regime (runs costing minutes) — exactly where the project's own theory says the DB wins.

Changes landed now: score.py exposes --timeout/--workers (the documented runs used settings the script couldn't produce) and a --strict mode closing the token-containment loophole a chattier weak model would exploit; a new validation/arity_fp.py harness audits the arity checker corpus-wide. All five existing harnesses were re-run on this box against 2.29-9 with the new DB: extractor 0 crashes, DB names 99.98% Magma-confirmed, typo recall 100% (49,456 injections), diff-diagnostics 7 known corpus artifacts.

3 · What I deliberately did not do

  • Run new LLM evals (Haiku arms). Highest-value next experiment, but it consumes API budget — flagged for your go-ahead rather than run unilaterally. The harness changes it needs (strict scoring, flags) are in.
  • OS-level sandboxing. The trusted-user posture is documented and unchanged; note the wrapper-escape fix closed the one path where the safe pass could execute code. When the audience widens, bwrap --unshare-all or systemd-run with PrivateNetwork/ProtectSystem around the run/execute paths is the cheap hardening (~11 ms cold start leaves plenty of budget).
  • UTF-16 position mapping. LSP positions are UTF-16 code units; tree-sitter emits byte columns and Magma's columns on non-ASCII lines are byte-expanded. Wrong only on lines containing non-ASCII before the diagnostic — rare in Magma source. Documented as a known limitation; a single conversion layer is the right fix.
  • References / definition / hover for workspace-defined symbols. The scan now caches per-file symbol sets; extending it to keep locations would light up definition/references/workspace-symbol for the user's own code. Natural next PR.

4 · Recommended roadmap (priority order)

  1. Haiku (and one more weak model) arms on all three benchmarks — the strategic question the project exists to answer. ≥5 trials/task, cluster-aware CIs, --strict scoring. Cheap in wall-clock on this box.
  2. Commit and instrument the generation harness — record model, prompts, tool-call counts, tokens, wall time per episode, so "efficiency" becomes tokens/dollars per solved task.
  3. Expensive-probe benchmark — tasks where one run costs minutes (large class groups, big Galois groups, point counts over large fields) with a hard run budget; the untested regime where the DB should win.
  4. Non-handbook task suite — parametrized instances (seeded, checker-scored) from real research workflows, immune to training-data contamination and answer-in-prompt leaks (the hard set has one: golay_mindist).
  5. Workspace symbol locations → definition/references/hover for project code (§3).
  6. Domain tags in the DB (package area / enumeration category) feeding magma_search — "elliptic curve intrinsics matching X".
  7. Handbook optional-parameter defaults merged at build time (kernel sigs' defaults exist nowhere else); .sig-file doc fallback for the Magma-less build path.
  8. Differential name;-oracle harness in validation/ (arities, ref patterns, doc presence for every name, every build) — it would have caught all four extraction bugs automatically.
  9. UTF-16 position codec; positionless-diagnostic polish; OS sandbox before widening the audience.
